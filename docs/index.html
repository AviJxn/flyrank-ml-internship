Predictive Content Decay & Refresh Prioritisation in Enterprise Search Engine Optimisation

Author: Ravi Ranjan  |  Track: Machine Learning Engineering  |  Repository: AviJxn/flyrank-ml-internship
Abstract
Enterprise search engine optimisation (SEO) teams face severe efficiency bottlenecks when scheduling editorial content updates using static heuristics, which routinely generate high tie rates and false alarms. To resolve this challenge, we developed a supervised Random Forest classifier that ranks decaying search assets using historical, pre-window Search Console performance signals. Evaluated across unseen client domains via a rigorous client-holdout GroupShuffleSplit design, the model achieves a Precision@50 of 0.820, substantially outperforming the static staleness baseline (Precision@50 = 0.680). The resulting probability queue directly integrates into an operational Content Action Playbook, delivering archetype-specific reason codes and mandatory human-review parameters. All pipeline evaluations were conducted on a public-safe slice of a 79-million-row production warehouse release.

1. Introduction & Problem Statement

In large-scale digital publishing, organic search traffic decay occurs silently across thousands of indexed URLs. Content operations teams operate under strict weekly editorial constraints—typically possessing the bandwidth to review and refresh only 20 to 50 articles per week.

Traditional portfolio management relies on static, rule-based heuristics (e.g., flagging any page untouched for 180+ days that maintains over 500 impressions). However, these rigid rules create significant operational friction: they produce high false-positive rates and fail to differentiate priority among tied scores. Consequently, highly valuable editorial budgets are frequently wasted refreshing stable, evergreen articles, while genuinely decaying assets suffer compounding traffic and revenue loss. This paper presents a machine-learned approach to resolve this operational inefficiency.

2. Data Overview & Scope

This analysis leverages a pseudonymised production warehouse release comprising approximately 81.8 million rows across 104 distinct client domains. The core schema includes:

  • dim_clients: Client account metadata and historical data ingestion start dates for Search Console and Google Analytics.
  • dim_content: Pseudonymised content item dimensions representing 519,606 unique URLs.
  • fact_content_daily_performance: Daily search performance metrics (78.8 million rows).
  • fact_content_query_90d: Salienated 90-day query distribution and tail performance metrics.

To preserve strict data integrity and ensure evaluation rigor, model development was constrained to the March 2026 mid-panel window. Post-window outcome columns were securely isolated to prevent prospective data leakage.

3. Methodology & Validation Design

We formulate content refresh prioritisation as a supervised binary classification and learning-to-rank problem. The binary target label $y_i$ flags pages experiencing a >20% impression degradation within trailing 30-day windows. We intentionally excluded all target-derived features (such as trend_pct) from the input matrix to eliminate target leakage.

To guarantee the model's ability to generalise to entirely unseen client domains, all models were evaluated using a Client-Holdout GroupShuffleSplit (75% training / 25% testing). This strict grouping ensures that no individual client's URLs appear in both the training and evaluation phases.

5. Limitations & Honest Framing

  • Non-Causal Indicators: A high predicted decay probability reflects a historical trajectory; it does not guarantee that updating the on-page text will overcome external algorithmic SERP shifts (e.g., the introduction of Google AI Overviews).
  • Unbalanced Panel Depth: Historical data depth varies significantly across client domains within dim_clients, inherently biasing models toward older, more established domains with richer search histories.
