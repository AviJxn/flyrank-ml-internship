Predictive Content Decay & Refresh Prioritization in Enterprise Search Engine Optimization

Author: Ravi Ranjan (Avi)  |  Track: Machine Learning Engineering  |  Repository: AviJxn/flyrank-ml-internship
Abstract
Enterprise search engine optimization (SEO) teams face severe efficiency losses when scheduling editorial content updates using static heuristics that generate high tie rates and false alarms. We address the challenge of ranking decaying search assets by training a supervised random forest classifier on historical, pre-window Search Console performance signals. Evaluated across unseen client domains via a strict client-holdout GroupShuffleSplit design, our model achieves a Precision@50 of 0.820, substantially outperforming the static staleness rule baseline (Precision@50 = 0.680). The resulting probability queue directly feeds an operational Content Action Playbook with archetype-specific reason codes and mandatory human review rules. All pipeline evaluations were conducted on a public-safe slice of the 79M-row production release.

1. Introduction & Problem Statement

In large-scale digital publishing, search traffic decay occurs silently across thousands of indexed URLs. Content operations teams operate under fixed weekly editorial constraints—typically capable of reviewing only 20 to 50 articles per week. Traditional management relies on static rule-based heuristics (e.g., flagging any page untouched for 180+ days with over 500 impressions). However, static rules create massive blocks of tied scores and produce high false-positive rates, causing editorial budgets to be wasted on stable evergreen articles while declining assets suffer compounding traffic loss.

2. Data Overview & Scope

Our analysis leverages the pseudonymized production warehouse release comprising ~81.8 million rows across 104 client domains:

  • dim_clients: Client account metadata and Search Console / Analytics data start dates.
  • dim_content: Pseudonymized content item dimensions (519,606 URLs).
  • fact_content_daily_performance: Daily search performance facts (78.8M rows).
  • fact_content_query_90d: Salienated 90-day query distribution and tail metrics.

To preserve data integrity while ensuring evaluation rigor, model development was conducted on the March 2026 mid-panel window, keeping post-window outcome columns strictly isolated.

3. Methodology & Validation Design

We formulate content refresh prioritization as a supervised binary classification and ranking problem. The binary target label $y_i$ flags pages experiencing a >20% impression drop in trailing 30-day windows. We intentionally exclude all target-derived features (such as trend_pct) to eliminate data leakage.

To test generalization on entirely unseen client domains, models were evaluated using a Client-Holdout GroupShuffleSplit (75% train / 25% test), ensuring that no client's URLs appear in both training and evaluation sets.

5. Limitations & Honest Framing

  • Non-Causal Indicators: High decay probability reflects historical trajectory; it does not guarantee that updating text will overcome external algorithmic SERP shifts (e.g., Google AI Overviews).
  • Unbalanced Panel Depth: History depth varies across client domains in dim_clients, biasing models toward older domains with established search history.

6. Content Action Playbook & Recommendations

Model output probabilities map into four distinct operational archetypes to guide editorial review:
